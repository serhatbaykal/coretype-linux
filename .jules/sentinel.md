## 2024-10-07 - [CRITICAL] Time-of-Check to Time-of-Use (TOCTOU) vulnerability in configuration and secret storage
**Vulnerability:** A TOCTOU race condition existed where `secrets.json` and its parent configuration directory were created without explicit tight permissions upfront, and instead a separate `chmod`-like call later tightened the permissions on the file. This left a small time window where secrets could potentially be exposed to unauthorized local users.
**Learning:** In Linux environments, relying on post-creation permission changes (e.g. `chmod`) for sensitive files and directories creates a predictable and exploitable window. The configuration directory was being created with default umask permissions which might allow read/execute for group/others.
**Prevention:** Always use atomic operations for creating sensitive files and directories. For Rust in Unix environments, use `std::fs::DirBuilder::new().mode(0o700).create()` and `std::fs::OpenOptions::new().mode(0o600).create(true).open()` by importing `std::os::unix::fs::{DirBuilderExt, OpenOptionsExt}` to ensure the correct restricted permissions are applied at the exact moment of creation, leaving zero window for exploitation.
