## 2024-03-24 - [CRITICAL] Command Injection Bypass in System Actions
**Vulnerability:** The application was vulnerable to command injection bypass in the `execute_system_action` command parsing. It only split by whitespaces to look for forbidden commands (like `sudo`), which meant an attacker could bypass the check and execute restricted commands by chaining them using shell operators (e.g. `echo a;sudo bash` or `ls&&sudo rm -rf /`).
**Learning:** Checking for forbidden keywords purely by tokenizing whitespace is insecure because shell control characters (`;`, `&`, `|`, `\n`) can be used to construct new commands seamlessly without relying on spaces. We must sanitize such delimiters before tokenizing or use a formal parser.
**Prevention:** Sanitized command strings by replacing delimiters (`|`, `&`, `;`, `\n`) with whitespaces *before* checking tokens. In the future, avoiding user-space `sh -c` entirely and parsing commands systematically (using `std::process::Command` argument arrays directly, if possible) would prevent shell operators from being evaluated at all.
